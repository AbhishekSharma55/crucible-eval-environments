The remaining fallback is attrs PR #1187; its changed symbols could not be

breaking collection at the parent can make an entire fix-side file appear
transitioned. These cases count as candidates, never as “tests fixed.”

## Task 2: mechanical leakage detector

The deterministic detector:

1. Parses added lines and fix-side AST nodes for functions, methods, classes,
   parameters, constants, attributes, and new paths.
2. Uses `git grep -w` at the parent for identifiers and `git cat-file -e` for
   paths. Only names absent from the parent are new gold identifiers.
3. Searches the statement for those new names.
4. Independently checks literal diff syntax, `file.py:line` references, copied
   added-code spans, and imperative fix instructions paired with a new gold
   identifier.

Every verdict contains structured evidence. The copied-code threshold is
**eight lexical tokens**, selected before eval outputs or labels: it covers one
meaningful expression or call while avoiding ordinary API prose. Comment-only
added lines are excluded. No threshold is data-tuned. Tests include the required
case where a pre-existing function is named and correctly remains leak-free.

## Task 3: human validation

The CLI shows one statement and its gold patch, then records `leak_free`,
`leaked`, or `unsure`, a note, human identity, and UTC timestamps. It hides the
detector verdict during labeling.

The committed 50-item set uses seed `55317` to sample uniformly from the natural
union of complete B0/B1/B2 outputs. It contains 19 B0, 14 B1, and 17 B2
statements. Detector verdict was not used for selection: its natural predicted
rate is 47 leak-free and three leaked, with no artificial balancing.

Labels are **pending human review**. This agent supplied none. Afterwards,
`make review-metrics` emits the 2×2 matrix, TPR, TNR, Cohen's κ, and disagreements
with evidence. Fitness requires TPR and TNR ≥0.90; either below 0.80 requires
rule revision, not relabeling.

```bash
make review-set
make review-labels LABELER='real human identity'
make review-metrics
```

## Task 4: baselines and primary metric

All model calls are pinned to
[`deepseek/deepseek-v4-flash`](https://openrouter.ai/deepseek/deepseek-v4-flash).
The request hash covers model, messages, temperature, and token cap. Replay is
the default and hard-fails on a miss. Record mode stores the raw response,
per-call tokens, API-reported cost, latency, and hash; replay needs no key.

| Baseline | n | Leak-free validated rescues | Rate | Cost / candidate | Latency / candidate |
|---|---:|---:|---:|---:|---:|
| B0 title template | 100 | 88 | 88.0% | $0 | 0 s |
| B1 single prompt | 100 | 89 | 89.0% | $0.000177 | 3.649 s |
| B2 retry + warming | 100 | 95 | 95.0% | $0.000227 | 5.048 s |

B0's 12 leaks triggered 22 new-identifier, seven imperative-fix, and two
copied-code findings; statements can trigger multiple rules. Its primary metric
is 88/100 because all sampled environments already revalidated.

B1 makes one temperature-0 call. B2 uses the same prompt at temperatures 0,
0.125, 0.25, 0.375, and 0.5, stopping at the first detector pass. The
temperature-0 request is shared by hash. Eighty-nine cases stopped after one
attempt; one after two, one after three, three after four, and six exhausted all
five. Five remained leaked. A conservative preflight caps baseline spend at $6;
API-reported cost is authoritative. A complete replay with
`OPENROUTER_API_KEY` removed reproduced 88%, 89%, and 95%.

DeepSeek's optional reasoning was explicitly disabled. An initial 19-call
recording batch omitted that setting; one response spent its full completion
budget on reasoning and returned no statement. Those calls were discarded from
baseline results but their $0.004627 cost remains included in total spend.

```bash
OPENROUTER_API_KEY=... python3 -m scripts.run_baselines all --fixture-mode record
env -u OPENROUTER_API_KEY python3 -m scripts.run_baselines all --fixture-mode replay
```

## Task 5: solvability control

The sampler takes 30 detector-passing B2 rescues and 30 accepted issue-backed
controls. The one-step solver sees the statement and parent source only. Its
prompt builder never reads the gold source or hidden test patch. Hidden tests
and the proposed fix run in Docker with `--network none`.

Each environment gets one attempt, one model step, a 600-second test cap, and a
shared $12 solver-spend cap. Patches that modify hidden tests are rejected.
Success requires a clean selected-test exit and every credited node ID passing.

| Group | n | Attempted | Solved | Solve rate |
|---|---:|---:|---:|---:|
| B2 rescued | 30 | 30 | 6 | 20.0% |
| Real issue-backed control | 30 | 30 | 5 | 16.7% |

The rescued 95% Wilson interval is 9.5%–37.3%; the control interval is
7.3%–33.6%. The bands overlap heavily, so this sample gives no evidence that
rescued statements are substantially easier through leakage or harder through
vagueness. It also has a floor effect: after syntax-only normalization, 26
proposed patches still failed application and 22 applied but failed tests.
Eleven solved and one rescued request hit the 180-second model cap.

The syntax normalization uses Git's `--recount` for stale hunk counts and
`-p0` for repository-relative unified-diff paths. It changes no proposed
content, applies equally to both groups, and is covered by a unit test. Solver
fixture cost was $0.058895. Keyless replay reran all 60 sandbox checks and
reproduced both rates.

```bash
make solvability-set
OPENROUTER_API_KEY=... python3 -m scripts.run_solvability --fixture-mode record
env -u OPENROUTER_API_KEY python3 -m scripts.run_solvability --fixture-mode replay
```

## Spend, headroom, and definition-of-done audit

Total API-reported OpenRouter spend is **$0.086225**: $0.022702 for usable
baseline fixtures, $0.058895 for solver fixtures, and $0.004627 for the
discarded reasoning-enabled calls. One timed-out solver request returned no
usage object, so any provider-side partial charge for that call is unknown; even
the conservative project caps remain far below the $20 budget.

B2 at 95% leaves only five percentage points of detector-measured headroom. That
is close enough to ceiling that Phase 3 cannot win merely by adding retries or
minor prompt polish. It needs either fewer leaked tail cases at meaningfully
lower cost/latency, or evidence on a stricter human-validated measure. The equal
solvability rates are reassuring, but human detector validation is still
load-bearing before treating 95% as a trustworthy primary result.
